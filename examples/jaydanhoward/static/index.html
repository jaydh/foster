About

This page is a proof-of-concept port of jaydanhoward.com's nav shell onto Foster — a Rust web UI framework where the server owns all state and a thin WASM client just patches the DOM from fx-* attributes.

Dark mode and the contact dropdown are two independent machines sharing this page — theme (light/dark) wraps everything so its class applies site-wide, and nav (closed/open) is nested inside it for the dropdown alone. Every click here is a full HTTP round trip to the server and back before the DOM updates.

The highlighted nav link above, though, is deliberately not a machine — scroll position fires many times a second, and a state machine that means an HTTP round trip per transition. Continuous, high-frequency UI state like this belongs in plain JS (static/scrollspy.js, an IntersectionObserver toggling a class directly) sitting next to Foster, not modeled inside it.

Request Trace

Real data, no Foster machine at all — this snapshot of the request that already happened (client IP, geo via a real ip-api.com lookup, User-Agent, real process env vars) has nothing discrete or event-driven about it, so a plain fetch() in static/request_trace.js against a hand-rolled GET /api/request-trace route (src/request_trace.rs) is the whole implementation. This demo isn't behind Cloudflare, so the Cloudflare-specific fields are honestly absent rather than faked.

Cluster

Real Kubernetes data — src/cluster.rs uses the kube crate's Client::try_default() against the actual homelab k3s cluster this laptop already has kubectl access to (in-cluster service account first, local kubeconfig fallback, same as the real site). Deliberately not the CPU/mem/disk/Ceph panel from the production site — that's Prometheus-backed, and Prometheus's NodePort is bound to the home LAN interface only; this machine reaches the cluster over Tailscale, so that data genuinely isn't reachable from here. GitOps status and backup Job status both go through the k8s API server directly, which is reachable, so those are real. A single Foster machine (cluster) holds both lists in context; "Refresh" re-queries the cluster synchronously inside the transition's reducer.

Satellites

Heavier version of the same test: dozens of points animating every frame, not a coarse simulation step. static/satellites.js does the orbital math and drawing by hand; Foster owns run/pause and the three ring-visibility toggles below via a fourth independent machine (satellites), and the loop reads all four straight off the DOM — data-fx-state plus three fx-if marker elements, one per ring.

Conjunction Screening

This is the analog of the real site's conjunction screener: a background job that finishes on its own, polled by a widget with nothing to do with Foster. static/screening.js runs its own setInterval against a hand-rolled axum route (GET /api/screening, src/screening.rs) — not a Foster machine at all. The button carries both an fx-on (Foster's own tiny "idle"/"started" machine, just for the button label) and a plain click listener that kicks off the real background job. By this point in the page there are already four other machines' worth of SSE connections open — this section's own Foster machine makes five, sitting right at the six-per-origin HTTP/1.1 limit the framework's README calls out.

    Conway's Game of Life

    This canvas is not Foster — it's a plain requestAnimationFrame loop written by hand (see static/life.js). Foster only owns the two buttons below; the loop reads whether they're pressed by watching this section's data-fx-state attribute, the same DOM contract every [fx-machine] root exposes, and re-seeds the grid when the reset_nonce value changes. No round trip per frame, no binding into foster-client — just the DOM as the seam between a hand-rolled widget and server-owned chrome.
